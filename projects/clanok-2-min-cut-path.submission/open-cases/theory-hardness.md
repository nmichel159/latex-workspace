## 1. The problem and basic tools

Notation. `G = (V, E)` simple, undirected, `u != v` in one component. For `A subset V` with `u in A`, `v notin A`,
`delta(A)` is the set of edges with exactly one end in `A`; every minimum `u`-`v` cut is such a set, and "the
minimum cut `A`" means `delta(A)`. `H_A = (V, delta(A))` is the *cut graph* of `A`. For a `u`-`v` path
`P = x_0 x_1 ... x_l` (`x_0 = u`, `x_l = v`) let `even(P) = {x_i : i even}`, `odd(P) = {x_i : i odd}`.
`lambda(S, T)` = minimum number of edges separating the disjoint vertex sets `S` and `T`.

**PATH-IN-MIN-CUT.** Input `G, u, v`. Question: does some minimum `u`-`v` cut contain (the edge set of) a `u`-`v` path?
Equivalently: is `u` connected to `v` in `H_A` for some minimum cut `A`? (A `u`-`v` walk in `H_A` contains a
`u`-`v` path in `H_A`.)

**Lemma 1.1.** `cp(u,v) = c(u,v)` iff PATH-IN-MIN-CUT holds for `(G, u, v)`.
*Proof.* If `delta(A)` is a minimum cut containing a path, it is a cut-path of size `c`, and `cp >= c` (Lemma 2.3 of
article 1). Conversely let `S` be a cut-path with `abs(S) = c`. `S` contains a `u`-`v` cut, which has `>= c` edges, so
`S` itself is a `u`-`v` cut of size `c`; with `A` the component of `u` in `G - S`, `delta(A) subset S` is a `u`-`v` cut,
so `delta(A) = S` by minimality, and `S` contains a `u`-`v` path. ∎

**Lemma 1.2.** Let `delta(A)` be a minimum cut containing a `u`-`v` path `P = x_0 ... x_l`, and `f` any maximum `u`-`v`
flow (unit capacities). Then (i) `x_i in A` iff `i` is even, so `l` is odd; (ii) every edge of `delta(A)` carries one
unit of `f` from its end in `A` to its end outside `A`; hence the edge `x_i x_{i+1}` carries flow from `x_i` to
`x_{i+1}` for even `i` and from `x_{i+1}` to `x_i` for odd `i`; (iii) `l <= c(u,v)`; (iv) in a decomposition of `f`
into `c` edge-disjoint `u`-`v` paths, `P` uses at most one edge of each.
*Proof.* (i) Every edge of `P` has one end in `A`, and `x_0 = u in A`; induction; `v notin A` gives `l` odd.
(ii) The net flow out of `A` is `c = abs(delta(A))` and each edge carries at most one unit, so every edge of `delta(A)`
carries exactly one unit outwards. (iii) `P subset delta(A)`. (iv) A flow path leaves `A` once more than it enters it,
and it cannot enter `A` (an edge of `delta(A)` carrying flow into `A` contradicts (ii)), so it crosses `delta(A)`
exactly once. ∎

**Lemma 1.3 (O3 for every length).** For a `u`-`v` path `P` of odd length the following are equivalent:
(a) `P` lies in some minimum `u`-`v` cut; (b) `lambda(even(P), odd(P)) = c(u,v)`; (c) `c_{G-P}(u,v) = c(u,v) - abs(P)`.
*Proof.* (a)⇒(b): the minimum cut `A` contains `even(P)` and misses `odd(P)` (Lemma 1.2), so
`lambda(even, odd) <= c`; any set separating `even(P) ∋ u` from `odd(P) ∋ v` is a `u`-`v` cut, so `>= c`.
(b)⇒(a): a set `A` with `even(P) subset A`, `A ∩ odd(P) = ∅`, `abs(delta(A)) = c` is a minimum `u`-`v` cut, and every edge of
`P` joins an even and an odd vertex, so `P subset delta(A)`. (a)⇒(c): `delta(A) - P` is a `u`-`v` cut of `G - P` of size
`c - abs(P)`, and removing `abs(P)` edges lowers `c` by at most `abs(P)`. (c)⇒(a): `P` plus a minimum cut of `G - P` is a
`u`-`v` cut of `G` with `c` edges containing `P`; as in Lemma 1.1 it equals `delta(A)` for the component `A` of `u`. ∎

**Corollary 1.4.** PATH-IN-MIN-CUT is in NP (certificate `P`, test (c) by two max-flows), and for every fixed `k` the
pairs with `c(u,v) <= k` are decided in time `O(n^(k-1) * k * abs(E))` (enumerate the paths of odd length `<= k`,
Lemma 1.2 (iii), test (b) by one max-flow of value `<= k` each).

## 2. NP-completeness

### 2.1 Construction

Input: a CNF formula `phi` with clauses `C_1, ..., C_m` (`m >= 1`) over variables `x_1, ..., x_n`; a clause is a
non-empty list of literals, repetitions allowed (3-SAT is the case of three literals per clause). `L` = total number
of literal occurrences. Put `c0 = (m + 1) + 2L` and `M = c0 + 2`.

- `K_A`: a clique on `M` vertices, among them `u = h_0, h_1, ..., h_m` and `a_1, a_2` (the other `M - m - 3 >= 2L >= 2`
  vertices are *fillers*).
- `K_B`: a clique on `M` vertices (disjoint from `K_A`), among them `beta_0, ..., beta_m` with `beta_m = v`, and
  `b_1, b_2` (and fillers).
- `F = {h_k beta_k : k = 0, ..., m}` (the only edges between `K_A` and `K_B`).
- For the `j`-th literal of `C_k` a new *occurrence vertex* `o = o_{k,j}` (`k = 1..m`):
  - literal `x_i` (*positive*): `o` adjacent to `beta_{k-1}, beta_k` and to `a_1, a_2`;
  - literal `not x_i` (*negative*): `o` adjacent to `h_{k-1}, h_k` and to `b_1, b_2`.
- *Sync edges*: the occurrence vertices of each variable `x_i` (the set `O_i`) are joined into a path.

`G` has `2M + L` vertices and `M(M-1) + (m+1) + 4L + sum_i (abs(O_i) - 1)` edges; it is computed in polynomial time.
Every occurrence vertex has exactly two neighbors in `K_A` and two in `K_B`.

For an assignment `tau` put `A_tau = K_A ∪ ⋃{O_i : tau(x_i) = true}`.

### 2.2 Correctness

**Lemma 2.2 (forcing).** Every minimum `u`-`v` cut `A` satisfies `K_A subset A` and `A ∩ K_B = ∅`; `c(u,v) <= c0`.
*Proof.* The edges leaving `K_A` are the `m + 1` edges of `F` and two edges at each occurrence vertex, so
`abs(delta(K_A)) = c0` and `c <= c0`. If `a in K_A - A`, the `M - 1` edge-disjoint `u`-`a` paths of the clique (the edge `ua` and
`u w a`, `w in K_A - {u, a}`) all cross `delta(A)`, so `abs(delta(A)) >= M - 1 = c0 + 1 > c`. The same argument with `v`
and `K_B`. ∎

**Lemma 2.3 (all minimum cuts).** For every `A` with `K_A subset A subset V - K_B`, `abs(delta(A)) = c0 + s(A)`, where `s(A)` is the
number of sync edges in `delta(A)`. Hence `c(u,v) = c0`, and the minimum `u`-`v` cuts are exactly the sets `A_tau`
(one for each assignment of the variables that occur in `phi`).
*Proof.* Clique edges never lie in `delta(A)`, all `m + 1` edges of `F` do, and an occurrence vertex contributes
exactly two edges (its two edges to `K_B` if it lies in `A`, its two edges to `K_A` otherwise). With Lemma 2.2, `A` is
minimum iff `s(A) = 0` iff each `O_i` (connected by its sync path) lies wholly inside or wholly outside `A`. ∎

**Lemma 2.4 (cut graphs).** For every assignment `tau`: `u` and `v` are connected in `H_tau = (V, delta(A_tau))` iff
`tau` satisfies `phi`.
*Proof.* Call an occurrence vertex *true* if its literal is true under `tau`. A positive occurrence of `x_i` lies in
`A_tau` iff `tau(x_i)` is true, a negative one iff `tau(x_i)` is false. By Lemma 2.3 the edges of `H_tau` are: `F`; for a
true occurrence vertex of `C_k`, its two edges to `beta_{k-1}, beta_k` (positive) or to `h_{k-1}, h_k` (negative); for a
false one, its two edges to `a_1, a_2` (positive) or to `b_1, b_2` (negative). Let `L_k = {h_k, beta_k}` (joined by `F`).
(⇐) A true literal of `C_k` gives a vertex adjacent in `H_tau` to `L_{k-1}` and to `L_k`; so `L_0 ∪ ... ∪ L_m` lies in one
component, and `u in L_0`, `v in L_m`.
(⇒) Let `C_k` be false under `tau` and `W = L_0 ∪ ... ∪ L_{k-1} ∪ {true occurrence vertices of C_1, ..., C_{k-1}}`.
In `G`, `h_j` and `beta_j` are adjacent outside their cliques only to each other and to occurrence vertices of
`C_j, C_{j+1}`; in `H_tau` only to true ones. For `j <= k - 1` these lie in `W` (clauses `<= k - 1`) or belong to `C_k`,
which has no true occurrence vertex. A true occurrence vertex of `C_j` is adjacent in `H_tau` only to `L_{j-1} ∪ L_j`.
So no edge of `H_tau` leaves `W`; `u in W` and `v = beta_m notin W` (`m >= k`). ∎

**Theorem 2.5.** PATH-IN-MIN-CUT is NP-complete. It remains NP-complete on instances with `d(u,v) = 2` in graphs of
diameter 3 (exactly 3).
*Proof.* NP: Corollary 1.4. Hardness: `phi` is satisfiable iff some `H_tau` connects `u` and `v` (Lemma 2.4) iff some
minimum cut contains a `u`-`v` path (Lemma 2.3). Distances: `u = h_0` and `v = beta_m` are not adjacent (`m >= 1`) and
have the common neighbor `h_m`, so `d(u,v) = 2`. Every vertex lies in `K_A` or `K_B` or is an occurrence vertex with
neighbors in both cliques; two vertices of one clique are adjacent; `x in K_A`, `y in K_B` are joined by
`x h_m v y` (or shorter); an occurrence vertex is within distance 2 of every clique vertex; two occurrence vertices
`o, o'` are joined by `o - (neighbor of o in K_A) - (neighbor of o' in K_A) - o'`. So the diameter is at most 3, and a
filler of `K_A` and a filler of `K_B` have no common neighbor, so it is 3. ∎

**Corollary 2.6.**
(a) Deciding `cp(u,v) = c(u,v)` is NP-complete, also for `d(u,v) = 2` and diameter 3 (Lemma 1.1).
(b) The decision version of Min Cut-Path is NP-complete on graphs of diameter 3, already with `d(u,v) = 2` and threshold
`b = c(u,v)` (for `d = 2`, `cp <= b = c` iff `cp = c`). Computing `cp(u,v)` is NP-hard for pairs with `d(u,v) = 2`.
(c) Deciding `cp(u,v) = c(u,v) + d(u,v) - 1`, i.e. whether the union of a minimum cut and a shortest path is a minimum
cut-path (article 1, Remark 5.6), is coNP-complete, also for `d = 2` and diameter 3. (In coNP: a smaller cut-path is a
certificate of the complement. Hard: for `d = 2`, `cp in {c, c+1}`, so `cp = c + d - 1` iff not `cp = c`.)
(d) Lengths: if `phi` is satisfiable, every `u`-`v` path inside a minimum cut of `G` has length at least `2m + 1`.
(It lies in some `H_tau` and, by the proof of Lemma 2.4, must leave each set `W_k`, `k = 1..m`, through an occurrence
vertex of `C_k` and its two edges; with Lemma 1.2 (i) the length is odd.) So no constant bound on the length of
the paths that have to be tested exists unless P = NP, and the weak form of O4 fails for general graphs (and for
diameter 3). Smallest instances (one-literal clauses, `hardness/results-examples.txt`): `phi = (x_1) and (x_1)`
gives 20 vertices, 84 edges, `c = 7`, `d = 2`, diameter 3, two minimum cuts, and every path inside a minimum cut has
length 5 (definition-based test: only length 5 occurs).

Remarks. (1) The forcing cliques make `c(u,v)` grow with `phi`; this is unavoidable: bounded `c(u,v)` is polynomial
(Corollary 1.4). (2) The graphs are far from DC: fillers of `K_A` and `K_B` are at distance 3 with `c = M - 1`.
(3) Clauses of any length are allowed; with 3 literals the reduction is from 3-SAT, NP-complete (article 1 cites
Cook 1971 and Karp 1972 for it).

## 3. O5: a vertex adjacent to `u` and `v`

**Lemma 3.1.** Let `G' = G + w` with a new vertex `w`, `N(w) = {u, v}`. Then (i) for every `A' subset V ∪ {w}` with
`u in A'`, `v notin A'`: `abs(delta'(A')) = abs(delta(A' ∩ V)) + 1`; so `c' = c + 1` and the minimum cuts of `G'` are `A` and
`A ∪ {w}` for the minimum cuts `A` of `G`; (ii) `d'(u,v) = min(d(u,v), 2)`; (iii) some minimum cut of `G'` contains a
`u`-`v` path iff some minimum cut of `G` does; (iv) `cp'(u,v) = c'(u,v)` iff `cp(u,v) = c(u,v)`.
*Proof.* (i) Exactly one of `uw`, `wv` lies in `delta'(A')` (`wv` if `w in A'`, `uw` otherwise); all other edges are
edges of `G`. (ii) Clear. (iii) ⇐: a path in `delta(A)` lies in `delta'(A)`, a minimum cut by (i). ⇒: let `P'` lie in
the minimum cut `delta'(A')`. If `w notin P'`, `P'` is a path of `G` inside `delta(A' ∩ V)`, minimum by (i). If `w in P'`,
then `P' = u w v` because `N(w) = {u, v}`, and both `uw` and `wv` would lie in `delta'(A')`, which (i) excludes.
(iv) Lemma 1.1. ∎

Consequences. (1) Every instance of PATH-IN-MIN-CUT reduces to one with `d(u,v) <= 2` (and `d = 1` is a trivial yes);
together with any NP-hardness proof this gives NP-hardness for `d(u,v) = 2`. Theorem 2.5 has `d = 2` already, so O5 is
not needed there. (2) `w` has degree 2, so it creates no pair outside DC by itself, but it raises `c(x,y)` by at most 1
for old pairs; a pair with `d(x,y) >= 3`, `c(x,y) = 2` can become a pair with `c = 3` at distance `>= 3` (when the new
route `u w v` does not shorten it), so **O5 does not preserve DC** in general.
Check: `check_lemmas.py`, all 39692 ordered pairs of the connected graphs with `<= 7` vertices: `c' = c + 1`,
`d' = min(d, 2)`, same answer; 0 failures.

## 4. Structural lemmas (any graph)

**Lemma 4.1 (small sets).** Let `delta(A)` be a minimum `u`-`v` cut containing a `u`-`v` path `P`, and let
`X subset V - {u, v}` with `abs(delta(X)) <= 3`. Then `P` has no vertex in `X`.
*Proof.* Suppose it has. `P` starts and ends outside `X`, so every maximal subpath of `P` inside `X` uses two edges of
`delta(X)`; as `abs(delta(X)) <= 3` there is exactly one such subpath `x_1 ... x_2`, entered by `e_1 = a x_1` and left by
`e_2 = x_2 a'` (`a, a' notin X`); let `e_3` be the possible third edge of `delta(X)`. All edges of `P` lie in `delta(A)`.
Moving `X` to one side changes `delta(A)` only on `E(X) ∪ delta(X)`, and afterwards no edge of `E(X)` is cut.
Case `a`, `a'` on the same side: move `X` to that side; before, `e_1, e_2` were cut (`>= 2`); after, at most `e_3`
(`<= 1`). Case `a`, `a'` on different sides: the subpath `a x_1 ... x_2 a'` has odd length (Lemma 1.2 (i)), so
`x_1 ... x_2` has odd length `>= 1` and its edges are cut: before `>= 3`; after moving `X` to either side exactly one
of `e_1`, `e_2` and possibly `e_3` are cut: `<= 2`. In both cases the new set still contains `u` and not `v`
(`u, v notin X`) and gives a smaller `u`-`v` cut, a contradiction. ∎

**Corollary 4.2.** Let `P` lie in a minimum `u`-`v` cut and let `x` be an internal vertex of `P`.
(a) `deg(x) >= 4` (`X = {x}`).
(b) For `t in {2, 3}`: if `c(u,v) > t` then `c(x,u) > t` and `c(x,v) > t`. (`t = 2` is O1.)
*Proof of (b).* Suppose `c(x,u) <= t`; take `Y ∋ x`, `u notin Y`, `abs(delta(Y)) <= t`. If `v notin Y`, Lemma 4.1 is
contradicted, so `v in Y`. Since `c(x,u) >= min(c(x,v), c(v,u))` and `c(u,v) > t`, also `c(x,v) <= t`: take `Z ∋ x`,
`v notin Z`, `abs(delta(Z)) <= t`; as before `u in Z`. Posimodularity of the cut function,
`abs(delta(Y)) + abs(delta(Z)) >= abs(delta(Y - Z)) + abs(delta(Z - Y))` (the difference is twice the number of edges between
`Y ∩ Z` and `V - (Y ∪ Z)`), gives `2t >= abs(delta(Y - Z)) + abs(delta(Z - Y)) >= 2c(u,v) > 2t`, since `Y - Z ∋ v`, `∌ u` and
`Z - Y ∋ u`, `∌ v`. The case `c(x,v) <= t` is symmetric. ∎
(c) In DC with `c(u,v) >= 3`: all vertices of all paths inside minimum cuts lie in the class `Q_3(u) = {x : c(x,u) >= 3}`
and are pairwise at distance `<= 2` (O1 as stated by the lead, now proved). In the class "`d <= 2` or `c <= 3`" with
`c(u,v) >= 4`: the same with `Q_4(u)`. If `c(u,v) <= 3`, paths inside minimum cuts have length `<= 3` (Lemma 1.2), so
O3 decides the pair in polynomial time.

**Lemma 4.3 (crossing minimum cuts).** Let `delta(A)`, `delta(B)` be minimum `u`-`v` cuts. Then
(i) `abs(delta(A)) + abs(delta(B)) = abs(delta(A ∩ B)) + abs(delta(A ∪ B)) + 2 e(A - B, B - A)`; hence `A ∩ B` and `A ∪ B` are minimum
cuts and **no edge joins `A - B` and `B - A`**;
(ii) if `z notin {u, v}` is adjacent to `x in A - B` and to `y in B - A`, then `z in A ∩ B` or `z notin A ∪ B`, `deg(z) >= 3`,
and the path `x z y` lies in `delta(A ∩ B)` (if `z in A ∩ B`) or in `delta(A ∪ B)` (if `z notin A ∪ B`).
*Proof.* (i) Count edges between the four sets `A ∩ B`, `A - B`, `B - A`, `V - (A ∪ B)`: every edge type is counted
equally on both sides except edges between `A - B` and `B - A`, counted twice on the left only. Both `A ∩ B` and `A ∪ B`
contain `u` and not `v`, so their cuts have `>= c` edges, and the left side is `2c`. (ii) `z in A - B` or `z in B - A`
would give an edge forbidden by (i). If `z in A ∩ B`, both `zx`, `zy` lie in `delta(A ∩ B)`; if `deg(z) = 2`, moving `z`
out of `A ∩ B` lowers this minimum cut by 2. Symmetrically for `A ∪ B`. ∎
(According to the workspace reading note `knowledge/literature/PicardQueyranne1980.md`, the lattice part of (i) is
Corollary 3 of the Picard-Queyranne report; the report was not re-opened here, and the proof above is
self-contained.)
Note: `z in {u, v}` is possible (the 4-cycle `u x v y`).

11117 with 8 vertices (unordered pairs), 350968 pairs, 181970 with a path inside a minimum cut (182764 such paths):

|---|---|---|---|
| diameter `<= 3` | NP-complete | NP-complete | Theorem 2.5 |
| `d <= 3` or `c <= 2` | NP-complete | NP-complete | contains all graphs of diameter `<= 3` |
| `d <= 2` or `c <= 3` | open | open | Section 6; polynomial for pairs with `c(u,v) <= 3` (Cor. 4.2 (c)) |
| `c(x,y) <= 3` | polynomial (`O(n^2)` paths of length 3, one max-flow each) | open | Corollary 1.4; general Min Cut-Path with bounded `c` is article 1, question 2 |
| DC (`d <= 2` or `c <= 2`) | open | open | Section 6 |
| diameter `<= 2` | trivial: no for `d(u,v) = 2` | polynomial | article 1, Theorem 5.5 |

So DC is squeezed between an NP-complete class ("`d <= 3` or `c <= 2`") and an open one ("`d <= 2` or `c <= 3`").
Gadgets tried to move Theorem 2.5 into the two open classes (Section 6): a perfect matching between the cliques,
ears (vertices of degree 2) for the forcing and for distances, shared dummies, private and shared common neighbors
of occurrence vertices; all fail on positive/negative occurrence vertices of different variables (Section 6.2).

## 6. DC and "`d <= 2` or `c <= 3`": what blocks a reduction, and two refuted shortcuts

**6.1 Ears as virtual edges.** In DC a vertex of degree 2 (an *ear* between `p` and `s`) contributes to every minimum
cut exactly like an edge `ps`, gives `d(p,s) <= 2`, never lies on a path inside a minimum cut (Lemma 4.1), and is a
leaf or isolated in every cut graph `H_A`. This allows a sparser variant `G*` of the construction
(`hardness/dc_attempt.py`, `results-dc-attempt.txt`): cliques `K_A = {h_0..h_m, a_1, a_2}`, `K_B = {beta_0..beta_m, b_1, b_2}`
without fillers, the perfect matching `F' = F + {a_1 b_1, a_2 b_2}` (so every `K_B` vertex has a `K_A` neighbor and
the two cliques are within distance 2), occurrence vertices and sync edges as before, and the forcing done by
`t = 2L + 2` ears between `u` and every other vertex of `K_A` and between `v` and every other vertex of `K_B`
(`lambda(u, a) >= (abs(K_A) - 1) + t > abs(F') + 2L = c0'`, so Lemma 2.2 holds with `c0'`; Lemmas 2.3, 2.4 go through
unchanged, the ears of `K_A` joining the `u` side). Checked exactly on 11 formulas (60-338 vertices): `c = c0'`, the
minimum cuts are the `A_tau` (with the ears of `K_A`), answer = satisfiability, 0 failures. The **only pairs at
distance `>= 3` with `c >= 3` are pairs of a positive and a negative occurrence vertex**; those of the same variable
can be joined by an edge (it is never cut), so the true obstruction is **positive/negative occurrence vertices of
different variables**. Formulas without such a pair give graphs in DC (e.g. `(x_1) and (x_1)`: 60 vertices, in DC,
only a path of length 5), but they are trivially satisfiable.

**6.2 The obstacle.** Such a pair `x, y` lies in `Q_3(u)` (both lie on paths inside minimum cuts for suitable
formulas), so in DC it needs `d(x,y) <= 2`. If the variables of `x` and `y` are independent in the lattice of minimum
cuts (minimum cuts `A ∋ x`, `∌ y` and `B ∋ y`, `∌ x` exist, as needed to encode two free variables), Lemma 4.3 forbids
an edge `xy` and an ear `x - z - y`, and forces a common neighbor `z` of degree `>= 3` with `x z y` inside
`delta(A ∩ B)` or `delta(A ∪ B)`. In the construction this is a *join*: with `z` on the `A`-side, `x` (positive, not
used) and `y` (negative, used) become connected in every cut where both literals are false; with `z` on the `B`-side,
`x` (used) and `y` (not used) are connected whenever both literals are true. Every positive occurrence vertex `x` thus
links, whenever its literal is false, all used negative occurrence vertices it is joined to on the `A`-side, and every
negative one links, whenever its literal is false, all used positive occurrence vertices joined to it on the `B`-side.
Linking used occurrence vertices of clauses that are equal or consecutive is harmless (they already share a level);
linking clauses `k < k'` with `k' >= k + 2` connects `u` to `v` past the clauses in between, a *shortcut*, which turns
an unsatisfying assignment into a yes-instance whenever those clauses are false and the rest is satisfied.
*Claim (sketch).* If `phi` has positive occurrences in three pairwise non-consecutive clauses and negative occurrences
in three pairwise non-consecutive clauses, all six of distinct variables, every choice of sides creates a shortcut:
without shortcuts, each of the three positive vertices is joined on the `A`-side to at most one of the three negative
ones (they lie in pairwise non-consecutive clauses), so at least 6 of the 9 pairs are joined on the `B`-side; but each
negative vertex is joined on the `B`-side to at most one of the three positive ones, at most 3 pairs. Contradiction.
Joining a pair by an edge or an ear instead adds the term `[tau(x_i) != tau(x_j)]` to the cut value and, by
Lemma 4.3 (i), destroys the independence of the two variables. This rules out reductions of the form "clause gadgets
in series, one occurrence vertex per literal, independent variables, one common neighbor per pair" (sketch; it does
not rule out other designs). The same argument applies to "`d <= 2` or `c <= 3`" with `Q_4` in place of `Q_3` and
3-edge blobs in place of ears. **No proof that DC is polynomial follows**: the joins are not harmful in themselves (in
the example of 6.4 the path uses one).

**6.3 Weak O4 is false in DC (X6.1).** The lead's conjecture O4 (weak form) fails already in DC: the 10-vertex
graph `F(2)` of the experiments agent (`open-cases/experiments/results-family.txt`), edges
`0-1 0-2 0-4 0-6 0-7 1-2 1-3 1-5 1-8 2-3 2-4 2-6 3-4 3-5 3-9 4-5 4-7 5-8 5-9`, `u = 0`, `v = 5`, re-checked here with
`exact.py` and `mcp.py`: in DC, `d = 2`, `c = 5`, 9 minimum cuts, exactly one contains a `u`-`v` path, namely
`0 1 2 3 4 5` of length 5, `cp_brute = 5`. Hence O3 alone does not decide DC.

**6.4 One generator does not suffice in DC (X6.2).** For `x in V` let `down(x)` be the smallest minimum cut
containing `x` and `up(x)` the largest one avoiding `x`. The conjecture "if some minimum cut contains a path, one of
the `2n` cuts `down(x)`, `up(x)` does" holds for all 400 pairs (`d = 2`, `c >= 3`, answer yes) of the graphs with
`<= 8` vertices (`explore_extreme.py`), fails for the reduction graphs (`phi = (x_1)(x_2)(not x_3)(not x_4)`: 16
minimum cuts, one contains a path, `A_tau = down(o_1) ∪ down(o_2)`, `results-examples.txt`), and **fails in DC**:
`search_generators.py` found the 11-vertex DC graph
`0-3 0-4 0-6 0-8 0-10 1-2 1-4 1-6 1-7 2-5 2-7 2-9 2-10 3-7 3-8 3-10 5-7 9-10`, `u = 0`, `v = 2`: `d = 2`, `c = 5`,
31 minimum cuts (also by enumeration of all vertex sets in `mcp.py`), exactly one contains a `u`-`v` path:
`A = {0, 1, 3, 4, 6, 8}` with the path `0 10 3 7 1 2` (length 5, `cp_brute = 5`), and
`A = down(1) ∪ down(3) = {0,1,4,6} ∪ {0,3,8}` is not `down(x)` or `up(x)` for any `x`. Its 4-edge-connected core is
`Q = {0, 1, 2, 3, 7, 10}`; the vertices 4, 5, 6, 8, 9 are ears (`0~1` twice, `2~7`, `0~3`, `2~10`). The independent
generators 1 and 3 have the common neighbor 7 outside `A ∪ B` (`A = down(1)`, `B = down(3)`), as Lemma 4.3 demands,
and the path uses the join `3 7 1`. No such pair exists among the graphs with `<= 8` vertices.
Measure (`search_k.py`): `gen(A)` = the smaller of the number of inclusion-maximal sets `down(x)`, `x in A - A_min`,
and the number of inclusion-minimal sets `up(y)`, `y in A_max - A`; `k*(u,v)` = minimum of `gen(A)` over the
path-containing minimum cuts. Testing all cuts generated by at most `k` vertices costs `O(n^k)` searches, so a bound
`k* <= k` on DC would give a polynomial algorithm. Values: the 11-vertex DC graph above has `k* = 2`; the reduction
graphs have `k*` up to the number of variables (`(x_1)(x_2)(not x_3)(not x_4)`: 2; `(x_1)(x_2)(x_3)(not x_4)(not x_5)(not x_6)`: 3).
Hill climbing over DC graphs with 11-15 vertices (`search_k.py`, `search_k_seeded.py` started from the 11-vertex
graph; `results-k.txt`) found no DC pair with `k* >= 2` at all: the unstructured searches mostly drift to graphs
without any yes-pair. They say nothing about whether `k*` is bounded on DC; structured families are needed.

## 7. Polynomial special cases

1. `c(u,v) <= k`: `O(n^(k-1) k abs(E))` (Corollary 1.4); fixed-parameter tractable in `c(u,v)`, because `cp <= c` is the
   decision version with `b = c(u,v)`, FPT in `b` by article 1, Theorem 8.4.
2. `min(deg u, deg v)` bounded, or maximum degree bounded: `c(u,v) <= min(deg u, deg v)`, so case 1. (Contrast:
   Separating Shortest Path stays NP-complete when all vertices other than `u, v` have degree `<= 3`, article 1 after
   Theorem 3.10.)
3. Paths of bounded length `l`: `O(n^(l-1))` candidates, one max-flow each (Lemma 1.3).
4. Few minimum cuts: the minimum cuts are the closed sets of the residual digraph of one maximum flow
   (Picard-Queyranne, Theorem 1 of the report according to the workspace reading note; the enumeration in
   `exact.py` relies on it and agrees with two independent enumerations on all tested graphs); if the poset of its
   free strong components has width `w`, there are at most `(n+1)^w` of them
   (an ideal is determined by its antichain of maximal elements), each tested by one search in `H_A`. In Theorem 2.5
   the width is the number of variables.
5. `d(u,v) = 1`: yes. Diameter 2 and `d(u,v) = 2`: no (article 1, Theorem 5.5: `cp = c + 1`).
6. Not settled: planar graphs (the reduction uses cliques `K_M`), DC, "`d <= 2` or `c <= 3`".

## 9. Open questions and next steps

1. **DC** (author's focus): polynomial or NP-hard? Known now: O1 proved; weak O4 false; one generator not enough.
   A polynomial algorithm must handle cuts generated by several independent vertices; a hardness proof must avoid
   the shortcut obstacle of 6.2, i.e. not encode clauses as consecutive segments with one vertex per literal.
   Next: (i) whether the number of generators `k*` is bounded on DC (`search_k.py`); if it is, `O(n^k)` cuts
   suffice; (ii) the structure of `Q_3(u)` with ears ("core multigraph": every two core vertices adjacent, with a
   common core neighbor, or joined by an ear) as the right model for DC.
2. "`d <= 2` or `c <= 3`": the same questions with `Q_4`.
3. Bounded `c(u,v)` for the full Min Cut-Path (article 1, question 2): `cp = c` is FPT in `c`, `cp = d` (Separating
   Shortest Path) with bounded `c` is open.
4. Planar graphs.
5. For article 1: Corollary 2.6 answers questions 1 and 3 and half of 2 of its conclusion; whether to add it there is
   the author's decision (nothing in article 1 was changed).
